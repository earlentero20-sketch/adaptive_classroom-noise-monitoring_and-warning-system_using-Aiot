## Current code gates and metadata requirements

The dataset validator in `ml/data_pipeline.py` accepts `.wav` files only. Each
file must be readable uncompressed PCM (`comptype == "NONE"`), have a positive
sample rate, positive channel count, positive frame count, and a sample width
of 1, 2, 3, or 4 bytes. It checks for truncated data and incomplete frames.
It does not impose a fixed source sample rate, channel count, bit depth, or
duration. The experimental config preprocesses input to mono, 16 kHz, and a
1-second window; that is a preprocessing setting, not a WAV intake restriction.

Selected inputs requiring derived PCM WAV copies before this validator can
read them are:

- IMA ADPCM WAV: `23202__lg__lecture09.wav` (the standard-library WAV reader
  currently rejects format code 17).
- MP3: `352096__deleted_user_3667256__students-in-university-by-sielxm3d.mp3`,
  `425671__bparker4336__lecture.mp3`,
  `449511__12572598__theatre-class-lecture.mp3`, and
  `455052__maqsood5mail2worldcom__a-languge-teacher-can-make-a-lot-for-the-human.mp3`.
- AIFF: `504669__bpayri__group-of-students-talking-loud-in-classroom-valencian-and-spanish.aiff`.

If and only if the related source and rights reviews clear these files, a
possible non-overwriting FFmpeg conversion is below. It writes derived copies
under the separate dataset, mono 16 kHz signed 16-bit PCM. `-n` refuses to
overwrite an existing output. This command is proposed only and has not been
run; FFmpeg availability/support must be checked locally, especially for the
IMA ADPCM source. Preserve the originals and verify each output header and
audibility before metadata review.

```powershell

New-Item -ItemType Directory -Force -Path $outputRoot
```

## Source groups and experimental eligibility

After excluding the two byte-identical copies, the inventory records 7
different asset IDs and 7 different SHA-256 hashes for each proposed class.
That establishes only that the remaining files are not exact duplicates. It
does not prove independent recording sessions, distinct speakers, or separate
underlying source recordings. Freesound asset IDs identify separate catalog
entries, not necessarily independent recordings. The experimental fitter's
coded minimum of two reviewed `(source_id, original_recording_id)` groups per
class is therefore only conditionally met: verify source/session relationships
and assign matching group IDs to related material. Never count byte-identical
copies twice. The experimental mode fits all eligible
clips and produces no held-out evaluation metrics; it is not evidence of
generalization or classroom accuracy.

The current configured experimental dataset does not yet exist. A read-only
`--check-data` run against `ml/config/experimental-demo.json` returned
`dataset_root_missing`. After legitimate data preparation, the same check must
pass with no issues before the separate experimental runner can fit anything.
The ordinary train/validation/test baseline remains unchanged and is not
replaced by this full-fit demo path.
